## 1. 执行原则

1. **基于现状改，不从零重写。** 后端分层、Vue 前端、prompt YAML、jobs/orchestrator 已存在，所有改动必须沿现有结构推进。
2. **优先完成托管闭环。** 任务启动、步骤记录、SSE、断点恢复、定稿记忆，是第一轮重点。
3. **保留单章手动模式。** 章节编辑器和 `/api/projects/{id}/ai/{workflow}` 不能被托管模式破坏。
4. **llmwiki 不存正文。** wiki 只保存关键记忆、摘要、时间线、伏笔、角色、关系、知识和衔接信息。
5. **情感九步可配置。** 完整九步是 deep 模式，不是所有任务的默认负担。

## 3. 实施步骤

### Task 1：文档收敛

- 新增 `docs/PDR-v4.1-实施收敛版.md`
- 新增 `docs/开发要求-v4.1-实施收敛版.md`
- 在后续提交说明中明确 v4 是愿景，v4.1 是施工口径

### Task 2：托管任务模式

后端启动 job 时按以下规则处理：

```python
DEFAULT_SKIP_BY_MODE = {
    "fast": {"dialogue", "reader_pull", "anti_ai"},
    "standard": {"dialogue", "reader_pull", "anti_ai"},
    "deep": set(),
}
```

如果用户传入 `skip_steps`，与模式默认值合并。

### Task 3：断点恢复修复

修复：

- 不再查询不存在的 `step_index`
- 不再读取不存在的 `status`
- 使用 `step_status == "completed"` 判断步骤完成

### Task 4：前端 SSE 对齐

前端按后端事件契约处理：

- `chapter_started`：当前章节开始
- `chapter_completed`：章节完成
- `step` + `status`：步骤运行/完成/跳过/失败
- `completed` / `done`：任务结束

### Task 5：验证

必须运行：

```powershell
pytest backend/tests/test_mvp.py
cd frontend
npm run build
```

如测试环境缺依赖，必须说明具体缺失项和替代验证。
